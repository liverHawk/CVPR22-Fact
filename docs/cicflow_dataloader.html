CIC系フロー用 dataloader 実装指針

tutorial.html の画像前提（CUB/CIFAR/MiniImageNet: PIL → Resize/Crop → ToTensor）を、 CIC系フローデータ（CIC-IDS2017 / CIC-DDoS2019 など、中身はCICFlowMeter形式: 1フロー ≒ 80次元数値ベクトル + Label列）に読み替えるための指針です。同じ汎用ローダー (dataloader/cicflow) でデータセット名だけ変えて使います。 結論: 画像transformを捨て、行IDベースのtxt + 一括parquet + StandardScaler + MLP前提で作ります。 本ページはdataloaderが主題で、backbone変更は §6 に要点のみ記します。

1. CSV準備と洗浄（最初に一回だけ）

1

配置と列方針

曜日別CSVを data/<dataset>/csv/ に置き、結合・洗浄後を data/<dataset>/flows.parquet として固定します。小規模（数GB・メモリに載る）ならこれで可。大規模でメモリに載らない場合は flows.arrow（Arrow IPC・mmap）または分割parquetを使います（下記TIP）。

配置例
data/cicids2017/csv/Monday.csv ... Friday.csv
data/<dataset>/flows.parquet      # 洗浄済み結合版（正本）
data/<dataset>/feature_cols.json  # 使用列リスト
data/<dataset>/label_map.json     # Label -> 0..C-1
data/<dataset>/scaler.pkl         # base-train fitのStandardScaler
data/index_list/cicflowmeter/session_1.txt ... session_N.txt
  • 落とす列（推奨）: Flow ID, Source IP, Destination IP, Timestamp — 個体識別・時刻リーク源。Source/Destination Port は残すか落とすかを実験前に固定（残すとポートスキャン検出が自明になる場合あり）。
  • 残す列: 残りの数値約78列（CICFlowMeter v3で80前後。環境で変動するため feature_cols.json に記録）。
  • 洗浄順: 列名strip → inf/-inf → NaN → NaN行drop → 全定数列drop（例: Bwd PSH Flags 系が常に0の場合あり）→ Label前後空白除去。
大規模データはArrow / 分割parquetを使う（mmap・遅延読み）
Arrowはダメではなく、むしろ大規模では推奨です。違いは保存形式ではなく読み方です: pd.read_parquet一括読みは全量をRAMに載せるためOOMします。 pyarrow.memory_map + IPCやpyarrow.datasetならmmapでゼロコピー・行単位の遅延読みができます。 配置は data/<dataset>/arrow/train.arrow / test.arrow または dataset/train/*.parquet 分割とし、Dataset側は§4の大規模版テンプレ（インデックスのみ保持・__getitem__で1行変換）を使ってください。要 uv add pyarrow pandas。
CIC-IDS2017既知の汚れ
Infinity / NaN混入、空特徴行、攻撃名表記揺れ（例: Web Attack – Brute Force系の分割粒度）が報告されています。結合前に各CSVの Label 分布を集計し、マッピング表を label_map.json に固定してください。

2. セッション設計（クラス割当）

2

base / way / shot を先に決める

data_utils.set_up_datasets に書く4値を、攻撃ラベル割当と同時に決めます。CIC系はBENIGNが約8割で極端に不均衡のため、baseは多数派から、incrementalは少数攻撃から取ります。

設定例値備考
base_class6例: BENIGN + DoS Hulk + PortScan + DDoS + FTP-Patator + SSH-Patator
num_classes12粒度は実験前に固定（Web Attack系を1つに束ねる等）
way / shot2 / 5（または10）1新規session = 2攻撃 × 5フロー。CIFAR式 way*shot 行がtxt1件分
sessions4 (= 1 + (12-6)/2)総session数は自動計算で一致させる
  • testは get_session_classes（遭遇済み全クラス）で自動生成されるため、Datasetのtest側は index（クラスID配列）でフィルタできればよいです。
  • train/test分割は フロー単位の層化分割（例: train 80% / test 20%、seed固定）で行い、同一フローの重複混入を避けます。時刻順に割りたい場合は別途記録。
  • Heartbleed/Infiltration（数十件）はshot確保不可 → 除外か束ねるかを明記。無理に残すと再現性が崩れます。

3. session_*.txt の形式と生成

3

形式: グローバル行ID（整数・1行1件）を推奨

CUB式（画像パス列挙）はCSVが複数あると壊れやすいため、CIFAR式（整数ID列挙）を推奨します。flows.parquet の行番号をIDとします。

  • session_1.txt: base-trainの行ID全件（数万件になり得る。baseは全件学習が原則）。
  • session_2.txt〜: 各 way*shot 行。新規クラスから層化・均等shotで抽出。
  • scalerは session_1のtrainのみでfit し保存。新規session生成後にfitし直さない（リーケージ防止）。
scripts/make_cic_sessions.py（骨子）
import json, numpy as np, pandas as pd
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import train_test_split
import pickle

df = pd.read_parquet('data/<dataset>/flows.parquet')  # 洗浄済み・label_id列あり
train, test = train_test_split(df, test_size=0.2, stratify=df['label_id'], random_state=1)
train.to_parquet('data/<dataset>/train.parquet'); test.to_parquet('data/<dataset>/test.parquet')

# scalerはbase-trainのみでfit
base_ids = [0,1,2,3,4,5]
base_train = train[train.label_id.isin(base_ids)]
sc = StandardScaler().fit(base_train[json.load(open('data/<dataset>/feature_cols.json'))])
pickle.dump(sc, open('data/<dataset>/scaler.pkl','wb'))

# session_1.txt: base-trainの行ID
open('data/index_list/cicflowmeter/session_1.txt','w').write('\n'.join(map(str, base_train.index)))
# session_2.txt以降: 新規クラスからway*shotを層化抽出（seed固定）
rng = np.random.RandomState(1)
for s, cls_group in enumerate([[6,7],[8,9],[10,11]], start=2):
    picks = []
    for c in cls_group:
        pool = train[train.label_id==c].index.to_numpy()
        picks += list(rng.choice(pool, size=5, replace=False))
    open(f'data/index_list/cicflowmeter/session_{s}.txt','w').write('\n'.join(map(str, picks)))

4. Datasetクラス実装（表形式テンプレ）

4

dataloader/cicflow/cicflow.py

既存と同一シグネチャで作ります。PIL/transformsは不要、__getitem__ は (FloatTensor[D], int) を返します。

dataloader/cicflow/cicflow.py
import json, os, pickle
import numpy as np, torch
from torch.utils.data import Dataset

class CICFlow(Dataset):
    def __init__(self, root='data/', train=True, index_path=None,
                 index=None, base_sess=False, dataset='cicids2017'):
        self.root = os.path.expanduser(root)
        base = os.path.join(self.root, 'cicflowmeter')
        feats = json.load(open(os.path.join(base, 'feature_cols.json')))
        split = 'train.parquet' if train else 'test.parquet'
        import pandas as pd
        df = pd.read_parquet(os.path.join(base, split))
        sc = pickle.load(open(os.path.join(base, 'scaler.pkl'),'rb'))
        X = sc.transform(df[feats].to_numpy(np.float32))
        y = df['label_id'].to_numpy(np.int64)
        self.data, self.targets = X, y
        if base_sess:
            self.data, self.targets = self.SelectfromClasses(...)
        elif index_path is not None:   # incremental train: txtの行IDのみ
            self.data, self.targets = self.SelectfromTxt(...)
        elif index is not None:        # test: 遭遇済みクラスIDでフィルタ
            self.data, self.targets = self.SelectfromClasses(...)

    def __getitem__(self, i):
        return torch.from_numpy(self.data[i]), int(self.targets[i])
# 戻り値は FloatTensor[D], int。画像transformなし。
設計判断の記録
  • scalerをDataset内で毎回load（リーケージ防止・再現性）。fitは生成スクリプト側のみ。
  • train時augmentは画像のように必須ではない。必要なら __getitem__ で微小ガウスノイズを加える程度に留める。
  • num_workers は表形式では4程度で十分（画像ほどI/O負荷なし）。
  • 大規模版: 上記テンプレの pd.read_parquet→全量transform はRAMに載る場合のみ。大規模では下記のArrow遅延読み版を使う。全量 numpy 化しないこと。

6. Backbone側の注意（dataloader範囲外だが必須）

dataloaderだけでは学習は回らない
models/fact/Network.py: MYNET は dataset名で resnet20/resnet18（2D conv）を選択し、 pre_encode (layer2まで) / post_encode (layer3以降) に分割してMixupします。 [B,D] ベクトルはconvに入らないため、MLP encoder（例: Linear(D,256)→ReLU→Linear(256,512) を pre/postに分割）を別途追加する必要があります。詳細は tutorial.html §3 の手順に従い、 MYNET.__init__ / pre_encode / post_encode に cicflowmeter 分岐を追加してください。
