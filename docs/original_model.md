FACT（ForwArd Compatible Training）の方法論において、ResNetのような特定のバックボーンモデルを別のモデル（例えばVision Transformerや別のCNNアーキテクチャ）に変更する場合、FACTのメカニズムを機能させるために**維持しなければならない重要な機能・構造**がいくつかあります。

ソースに基づき、維持すべき主要な機能を以下に整理しました。

### 1. 中間層での分離とアクセス機能（多様体ミックスアップのため）
FACTの「先見性（Provident）」を実現するためには、モデルが入力画像そのものだけでなく、**中間層の特徴量**を操作できる必要があります。

*   **維持すべき機能**: モデル $\phi(x)$ を、中間層を境に前半 $h(x)$ と後半 $g(\cdot)$ に分離できる構造。
*   **理由**: FACTは**多様体ミックスアップ（Manifold Mixup）**を使用して仮想インスタンス $z$ を生成します。これは、異なるクラスのインスタンスを**中間層のレベルで混合**するプロセスです（$z = g[\lambda h(x_i) + (1-\lambda)h(x_j)]$）。
*   **要件**: したがって、ブラックボックスとして入出力だけを行うモデルではなく、**特徴抽出の途中でデータを取り出し、混合してから再入力できるアーキテクチャ**である必要があります。

### 2. プロトタイプベースの分類への対応（埋め込みモデルとしての性質）
FACTは、最終的な全結合層（FC層）の重みを固定的に学習するのではなく、特徴空間上の距離に基づく分類を行います。

*   **維持すべき機能**: クラスを「重みベクトル」ではなく、特徴空間上の**平均埋め込み（プロトタイプ）**として表現し、更新できる仕組み。
*   **理由**: ベースセッション後の増分学習では、新しいクラスのプロトタイプを抽出（平均化）して分類器に追加します。また、分類は**コサイン類似度**に基づいて行われるため、モデルの出力は正規化可能で、距離計測に適したベクトル空間を形成する必要があります。

### 3. 仮想プロトタイプの割り当てと最適化（拡張可能性のため）
モデルの出力層（または分類ヘッド）は、既知のクラス数に固定されず、柔軟に拡張・操作可能である必要があります。

*   **維持すべき機能**: 訓練中に、実際のクラス数 $|Y_0|$ に加えて、**仮想クラス数 $V$ 分の余分な出力ノード（仮想プロトタイプ $P_v$）**を割り当て、操作できること。
*   **理由**: FACTは、埋め込み空間を予約するために、データが正解クラスだけでなく仮想クラスにも属するように（双峰分布になるように）学習します。新しいモデルも、この「ダミーの出力先」を許容し、損失計算時に特定のロジットをマスク（無視）したり強調したりできる構造でなければなりません。

### 4. 推論時の確率的な統合能力（全確率の法則）
推論フェーズにおいて、単純な `argmax` だけでなく、複数の基底（プロトタイプ）からの寄与を計算できる必要があります。

*   **維持すべき機能**: 埋め込み $\phi(x)$ が、クラスプロトタイプと仮想プロトタイプの混合ガウス分布に従うという仮定に基づき、確率を計算できること。
*   **理由**: FACTの増分推論は、**全確率の法則**を用いて、情報量の多い仮想プロトタイプの影響を考慮して最終予測を行います。モデルが変わっても、この「埋め込みベクトルと複数のプロトタイプ間の関係」を計算する推論ロジック（式(8)〜(10)）は維持する必要があります。

### 結論
モデル（バックボーン）を変更する場合、単に画像を分類する能力だけでなく、以下の**「FACT互換」の構造的要件**を満たす必要があります。

1.  **分離可能性**: ネットワークの途中で特徴を混ぜ合わせることができるか？（$h(x)$ と $g(x)$）
2.  **距離計量性**: 出力特徴ベクトルがコサイン類似度などの距離学習に適しているか？
3.  **拡張性**: 出力層に「仮想の予約席」を設け、損失関数でそこへの配置を制御できるか？

これらが維持されていれば、ResNet以外のモデル（例：ViTなど）であってもFACTのトレーニングプロセスを適用することが理論上可能です。
